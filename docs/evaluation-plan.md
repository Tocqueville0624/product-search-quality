# 评估方案 — 已完成首轮冻结与最终测试

状态：本方案已落实为 `experiments/frozen_study.json`，最终结果见 `reports/test_metrics.json`。下文保留研究设计与指标规则；当前 test 已曝光，任何后续模型改进须遵守最后的探索/确认边界。实际配置、来源、模型/数据/代码哈希和冻结时点已有记录。

实际执行：从官方训练侧排除 1 个重合 query 的 3 行；59,947/14,940/22,458 个 train/validation/test 查询互斥。两个固定候选为无权重和逆频率类别加权的多项逻辑回归，17 个词汇特征；按 validation macro-F1 选后者。类别权重来自 train；加权分数只用来排序，未声称校准。人工案例只完成 48 条抽样，人工判断数为 0。公开报告同时保留 accuracy 下降、Complement precision 低和剩余错误的限制。

## 1. 观察单位与划分

主要观察单位是 US English 的一个搜索词—商品配对；同一查询下多条配对相关。四分类使用官方 large-version 样本。保留官方 train/test 标记，从官方 train 按 query group 确定性抽出验证集，不随机拆散配对行。

检查 `(product_locale, query_id)`、标准化查询文本、重复配对在集合间的重合。官方文档说按查询划分，但必须用实际文件核验。如果重合，需要在训练前记录处置，例如从训练侧移除受影响 query groups 以保持官方 test 完整；报告这已改变训练规模，不能未经说明与原基准成绩等同。

商品可跨不同查询出现；报告测试商品在训练中出现/未出现两个切片。相同商品出现不自动等于标签泄漏，但它改变泛化问题。第一版不训练商品 ID 查表模型，也不使用其他配对的测试标签。

先拟合训练数据中的文本转换、IDF、标准化或类别编码，再变换验证/测试。候选字段是否在实际预测时可获得必须记录；label、split、example ID、来源标记不能进入模型特征。

## 2. 模型比较

- B0：训练集多数类基线，报告各类别表现，不能只看 accuracy。
- M1：独立实现的词汇配对特征加简单四分类器，例如多项逻辑回归。特征可包括 token overlap、长度、品牌或数字的一致性；具体列表在开发期冻结。
- M2（可选）：一种有明确误差动机的改进。不能在看到测试成绩后反复选择模型。

主指标：macro-F1。辅助：各类 precision/recall/F1、混淆矩阵、predicted-Exact 的覆盖率和错误比例。报告类别支持数，固定 E/S/C/I 类别集合与零分母规则，不假定 Spark 内置名为 f1 的指标就是 macro-F1。

如果报告置信度，保存预测概率；概率校准只能在独立开发划分或开发期交叉验证中拟合并评估，不能在同一批标签上拟合后宣称校准有效。

## 3. 等预算的复核优先级

固定一个已训练模型，候选池 P = 其 argmax 预测为 E 的配对。错误指示 err = 1[发布标签不是 E]。这包括 S/C/I 三类，分别展示；业务危害不可直接视为相同或兑换成金额。

在同一个 P 内比较：

1. 固定随机种子的均匀随机抽查；用重复随机抽样给出波动。
2. 按 `1 - p(E)` 降序选择，即优先检查较不确定的 predicted-Exact。
3. 若增加模型分歧或其他规则，先在开发集写明计算方法，再冻结。

预算初值为 P 的 5% 和 10%，取整规则在代码中明确，同时报告实际检查条数。所有策略使用相同预算和确定性的平局处理。实际标签只用于事后评分，不能参与选样。不同模型产生不同的 P 时，分别报告覆盖率、池大小和错误数；不能把两个池上的抽查收益直接解释为某策略的净提升。

- Audit yield@b = 被检查条目中的错误数 / 检查条数。
- Error recall@b = 被检查条目中的错误数 / 整个 P 的错误数。
- 同时报告未检查池的剩余错误率、各类错误构成及分母。
- 空候选池、零错误和零预算的结果应标记为不适用，不能自动记成完美成绩。

这是一项用已有标签计算的离线复核策略模拟。不能把“被选出的已知错误数”称为实际人工修复数、节约工时或线上质量提升。

## 4. 切片、不确定性与人工分析

可预定义的切片包括查询长度、含数字查询、品牌相关查询、商品元数据缺失、训练中已见/未见商品。没有真实流量字段，配对条数或候选数不能冒充查询热度；短查询也不自动等于含糊查询。

主要指标和模型差值的不确定性按 query group 成组重采样；不把同一查询下的所有配对当成独立样本。报告样本数与区间，避免对小切片强下结论。

开发期人工检查约 50–100 条案例，含有意识抽取的误差类型。保存 example ID、原标签、预测、选择理由、人工意见和不确定性。若是有意选择的案例，案例比例不能推断总体误差率。单人复核不能声称多标注者一致性；保留原标签，不覆盖为“真值”。

## 5. 测试与后续迭代

最终测试前冻结数据版本、过滤、特征、模型、阈值、切片、预算、指标和配置。允许技术故障修复，但记录修复及重跑原因；不得根据测试成绩选择更好看的版本。

测试错误分析可以用于学习和下一轮设计。若据此改进，旧测试集上后续成绩标为 exploratory；新的确认性结论需要未参与开发的新 holdout。数据没有可用的行为时间序列时，不杜撰“时间外验证”。
